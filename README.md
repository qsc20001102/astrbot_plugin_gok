# 王者荣耀数据查询工具（astrbot_plugin_gok）

通过**王者营地官方接口**查询王者荣耀玩家数据的 AstrBot 插件。

插件使用自己的营地登录态查询数据：先在插件页面用微信或 QQ 扫码登录王者营地，
之后所有查询都由插件直接请求 `kohcamp.qq.com`，**不依赖任何第三方数据接口、
不需要申请任何 API 令牌**。

> 当前版本：**v2.5.1**。支持微信 / QQ 登录、对局回放、AI 分析持久缓存、上下线与最新战绩订阅推送；数据源为营地直连。完整变更见 [更新记录](CHANGELOG.md)，开发资料见 [接口参考](docs/camp-api-reference.md)。

| 能力              | 说明                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| 战绩查询          | 最近对局列表：英雄、KDA、评分、MVP/金牌/巅峰分变化、时长、对局段位                               |

| 微信 / QQ 登录    | 管理页可选择扫码方式，QQ 使用独立浏览器会话；取消、过期和卸载时回收浏览器                        |
| AI 对局分析       | 综合双方统计、轨迹与事件分析胜负原因；单局详情和 `分析` 指令共用数据库缓存                       |
| 订阅与会话推送    | 上线/离线和最新已完成战绩推送，网页管理订阅与多会话关联，未关联时暂停轮询                        |
| 昵称搜索与别名    | 先匹配人工别名、再匹配游戏昵称，未命中时在线搜索；同名候选按序号选择                             |

| 多账号            | 可登录多个营地账号，触发频控时自动切换                                                           |
| 登录态检测        | 管理页一键逐个检测所有账号，区分有效、失效、频控和网络异常                                       |
| 交互战绩          | 资料和战绩使用独立按钮，战绩列表使用营地图片资源，点击一场查看双方详情                           |

## 安装与启用

1. 在 AstrBot 管理面板 → 插件 中安装插件；使用 ZIP 时，包内目录应为 `astrbot_plugin_gok/`，包含 `main.py`、`metadata.yaml` 等文件。也可把插件目录放入 `AstrBot/data/plugins/astrbot_plugin_gok` 后重载。
2. AstrBot 版本要求为 **4.24.0 或以上**，依赖按 `requirements.txt` 安装：`aiohttp`、`aiosqlite`、`aiofiles`、`cryptography`、`playwright>=1.51,<2`。Playwright Python 包为必装依赖。
3. 打开插件页面 **王者荣耀数据查询工具 → 账号管理**，选择微信或 QQ 扫码登录。QQ 授权需要可用的 Chrome、Edge 或 Chromium，准备方式见下文。
4. 在 **玩家查询** 输入营地 ID、昵称或别名，选择查询资料 / 战绩；点击一场战绩查看概览和对局回放。
5. 如需 AI 分析，在插件配置 **AI 对局分析 → 分析模型** 中选择已配置的对话模型，再点击单局详情顶部右侧的“分析本场”或发送 `分析` 指令。
6. 如需推送，在目标聊天发送 `订阅状态 营地ID` 或 `订阅战绩 营地ID`；也可在 **订阅系统** 添加营地 ID，再添加完整会话 ID 并勾选要接收的订阅。首次检查建立基准，不推送旧记录。

### 扫码登录

管理面板 → 插件 → 王者荣耀数据查询工具 → **账号管理**，选择**微信 / QQ**，点击「获取二维码」，使用对应手机应用扫码并确认。
登录成功后登录态保存在 `data/plugin_data/astrbot_plugin_gok/camp_auth.json`，
后续查询无需重复登录；登录态失效时回到该页面重新扫码即可。

QQ 登录优先复用系统 Chrome、Edge 或 Chromium；没有系统浏览器时，在 AstrBot 的 Python 环境运行 `python -m playwright install chromium`。微信登录不需要浏览器。QQ 二维码在后台准备，页面会自动显示进度；刷新页面可恢复有效会话。

微信 / QQ 扫码及地图播放在 WebUI 中操作；聊天的 `营地登录` 提供状态和入口说明，`分析` 可以直接分析指定单局。网页、图片和文本共用业务模型。

### 从旧版本升级

升级后重载插件。技术目录名仍为 `astrbot_plugin_gok`，已有的 `data/plugin_data/astrbot_plugin_gok/camp_auth.json` 和 `gok.db` 继续使用，更新程序文件无需删除这些数据。

从 **2.5.0 升级到 2.5.1**：

- 更新插件并重载，数据库自动新增分析缓存、订阅与会话关联表；原账号和角色别名保留。
- AI 分析缓存默认保留 150 天；网页“分析结果”读取保存文字，“清除缓存”只删除当前对局结果。此前仅保存在内存中的分析没有历史数据可迁移。
- 状态和战绩轮询间隔分别默认 60 秒、120 秒，在插件配置 **订阅系统** 中修改；没有关联会话的目标不会轮询。
- `功能` / `帮助` 现在跟随 `query_output`，默认发送新的功能指南图片。希望继续收到文字时，将“查询指令输出方式”改为“文本”；四个订阅指令和主动推送始终输出文本。
- 更新后刷新插件页面，加载最新前端脚本和样式。四个管理页以及单局详情共用标题栏和外层留白，切换导航会回到顶部。

更早版本的升级说明：

- `角色查看` 更名为 `角色`，输出方式与战绩、资料、对局一起受 `query_output` 控制；`分析` 始终输出文本。
- 自动锐评及 `comment.*` 配置已移除。请在新的 `analysis.select_provider` 中选择分析模型；普通战绩查询不会自动调用模型。
- 原样保存的旧默认分析提示词会更新为当前格式；自定义提示词保留。将 `analysis.prompt` 留空可以使用新默认提示词。
- 名称映射拆分为真实游戏昵称、营地 ID 和人工别名。旧版手工名称会迁移为别名；成功查询自动更新昵称，管理页只允许设置或清除别名。

## 指令

指令参数可以是**营地 ID**（5~15 位数字）、**人工别名**或**游戏昵称**。数字直接查询；名称按“精确别名 → 精确游戏昵称 → 营地在线搜索”的顺序解析，不会自动选择本地模糊匹配结果。

### 查询

| 指令                             | 说明                                                             |
| -------------------------------- | ---------------------------------------------------------------- |
| `功能`                           | 按配置显示功能指南图片或完整指令文本                             |
| `战绩 [ID/别名/昵称] [场数]`     | 最近全部模式战绩，默认 10 场，最多 25 场，按配置输出图片或文本   |
| `排位战绩 [ID/别名/昵称] [场数]` | 仅查询和展示排位战绩                                             |
| `巅峰战绩 [ID/别名/昵称] [场数]` | 仅查询和展示巅峰战绩                                             |
| `资料 [ID/别名/昵称]`            | 段位、赛季胜率、本赛季常用英雄，按配置输出图片或文本             |
| `对局 [ID/别名/昵称] [序号]`     | 第 N 场对局的十人详情与出装，序号从 1 开始，按配置输出图片或文本 |
| `分析 [ID/别名/昵称] [序号]`     | 分析第 N 场对局，仅发送 AI 结论，默认第 1 场，需配置分析模型     |

“全部战绩”指全部对局模式，仍按近期战绩和指定场数展示。同名结果以编号、营地 ID、区服和段位输出；请在 60 秒内回复序号，或发送 `取消` / `退出`。选择按聊天与发送人隔离，超时后需重新发送查询指令。

多轮选择使用 AstrBot 官方的 [会话控制 API](https://docs.astrbot.app/dev/star/guides/session-control.html)。

### 订阅指令

| 指令                                       | 说明                                              |
| ------------------------------------------ | ------------------------------------------------- |
| `订阅状态 [ID/别名/昵称]`                  | 向当前群聊或私聊推送上线、离线变化                |
| `订阅战绩 [ID/别名/昵称]`                  | 向当前会话推送最新已完成的一场对局                |
| `查看订阅`                                 | 查看当前会话订阅，并返回可复制到网页的完整会话 ID |
| `取消订阅 [ID/别名/昵称] [状态/战绩/全部]` | 只取消当前会话的指定订阅；省略类型时取消两类订阅  |

### 角色名称映射

| 指令   | 说明                                                         |
| ------ | ------------------------------------------------------------ |
| `角色` | 按配置输出图片表格或文本，只展示游戏昵称、营地 ID 和人工别名 |

使用营地 ID 或昵称查询成功后，插件自动保存接口返回的真实游戏昵称和营地 ID，新记录的别名为空。
管理页只允许设置或清除别名，营地 ID 和游戏昵称不可手动修改；再次成功查询可以自动更新游戏改名，人工别名保留。

### 管理页面

页面顶部横向导航依次为“账号管理”“玩家查询”“角色别名”“订阅系统”，默认进入账号管理，导航末尾不再显示实时查询标识。资料和战绩以开放布局和列表展示；战绩的英雄 / 对局列设宽度上限，后续数据列均衡分配空间，详情出装列固定为最多六件装备的宽度。点击一场战绩进入“对局概览 / 对局回放”，桌面地图与事件列表并列，手机上纵向排列。

地图默认展示近 30 秒轨迹，可切换近 60 秒或全部轨迹；点击击杀等事件会定位到对应时间。轨迹按营地官方页面的每秒采样解析，死亡 / 复活信息用于避免画出不存在的移动。缺少玩家标识或回顾数据时返回明确提示，详情概览仍可查询。

地图玩家使用英雄头像和蓝红阵营边框；点击头像可切换轨迹。十八座防御塔沿用官方配置的位置，同一塔的推倒记录只生成一个最早消失时刻，拖回该时刻之前会恢复显示，避免重复记录造成多次摧毁。

顶部导航独立初始化，功能脚本加载失败仍可切换四页，并显示明确提示。发布入口使用普通打包脚本，开发源码继续按功能分文件维护，减少宿主沙箱内的模块加载依赖。

轨迹范围位于地图上方“显示轨迹”后面。播放与拖动时间轴时，地图画面会显示最近六个对局秒内发生的事件，并联动事件列表高亮；同时发生多条事件会合并提示，手动点选事件时保留指定提示。离开查询页会暂停播放。

详情将出装与召唤师技能分列，查询玩家用背景色标识；伤害 / 承伤下方显示队伍占比条。本场表现补充总伤害、总承伤、推塔数、野怪经济等字段，缺失统计显示“—”，胜方 MVP 与败方 SVP 分开。战绩胜利 / 失败用不同底色区分，荣誉图片容器保持透明。

回顾的交战记录显示双方参与人数、持续时间与击杀比分，点选可展开参与英雄；推塔记录标明推进阵营、建筑归属和分路 / 塔序，点选可查看参与英雄及该条记录内的伤害贡献占比。同一建筑可能返回多次事件，文档和页面不把事件条数当成摧毁次数；回顾贡献原值不直接当作单局建筑伤害。

- **检测全部登录态**：每个账号独立请求自己的营地资料，不自动换号；无效账号停止参与查询，
  网络异常和频控显示为暂无法确认，避免把它们误判为登录过期。
- **玩家查询**：同一个营地 ID 对应「查询资料」「查询战绩」两个按钮。网页用浅色背景与清晰列表
  展示头像、英雄、KDA、评分、荣誉、时长和段位。点击一场战绩进入详情，
  再返回列表时重新实时查询；按对局标识定位，避免列表更新后查看到另一局。
- **营地图片**：使用接口提供的头像、英雄图片、MVP、奖牌与背景。资料和战绩顶部使用排位模块
  返回的段位图、星级图；详情按每位玩家的 `finalEquips` 展示装备及名称，附带召唤师技能。
  页面不再展示“更多营地图片”。

资料昵称旁显示游戏状态，资料指令的图片和文本也展示同一状态。直接使用当前角色的 `gameOnline`：`0` 离线、`1` 在线、`2` 游戏中；未返回或未知状态码显示“未知”。这是查询时营地返回的状态，“游戏中”可以包含大厅、匹配等情形，正在进行对局需另外核对战绩接口。状态随每次资料查询更新，普通查询不增加后台轮询；状态订阅按配置独立检查。

## 工作原理

战绩图片沿用 WebUI“近期对局”的浅色列表与胜败底色；对局图片只展示比赛摘要和蓝红双方表格，出装最多六件、召唤师技能独立成列，并保留伤害与承伤占比条，不包含本场表现与对局回放。资料图片沿用 WebUI 的身份、段位、赛季统计和常用英雄布局；角色图片仅展示昵称、营地 ID、别名三列。

图片指令会先读取插件的 HTML 模板和公共片段，在本地合并后调用 AstrBot 自带的 `Star.html_render()`，不要求远端配置模板加载器。模板通过视口元信息设置报告宽度和最小截图高度，完整内容使用整页截图；支持该设置的渲染服务可以减少短表格下方的留白，参数见[官方渲染服务说明](https://github.com/AstrBotDevs/astrbot-t2i-service#api-endpoints)。
图片服务不可用时自动回退到查询结果文本；功能说明按同一配置发送简约图片或完整文本。将 `query_output` 改为 `文本` 后，战绩按每场一行展示时间、胜败、英雄、KDA、评分与荣誉；资料保留身份、段位与赛季摘要，对局保留双方阵容与 KDA，角色保留相同三列。

### 订阅系统与主动推送

网页导航末尾的“订阅系统”分为 **订阅状态、订阅战绩、会话推送**。前两个模块可以添加或删除营地 ID，显示最新状态/战绩、上次及下次轮询时间；会话模块可以添加完整会话 ID，并勾选该会话需要接收的多个状态和战绩订阅。未关联任何会话的订阅保留在列表中，但暂停轮询。同一类订阅的同一个玩家只查询一次，再分发给已关联会话。

聊天指令直接关联发起指令的当前会话：

```text
订阅状态 123456789
订阅战绩 123456789
查看订阅
取消订阅 123456789 状态
取消订阅 123456789 战绩
取消订阅 123456789
```

`取消订阅` 不带类型时取消当前会话的两类订阅，不影响其他会话。`查看订阅` 返回当前会话的完整 ID，形如 `平台实例ID:GroupMessage:群号` 或 `平台实例ID:FriendMessage:用户ID`，可复制到网页添加接收会话。主动推送依赖目标平台的主动消息发送能力；无法匹配平台或发送失败会显示在会话模块中。

主动发送沿用 [AstrBot 官方主动消息文档](https://docs.astrbot.app/dev/star/guides/send-message.html#主动消息)：保存 `event.unified_msg_origin`，后台使用 `context.send_message(session_id, MessageChain().message(text))` 发送，不另外实现消息平台接口。

状态从 `0` 变为 `1/2` 时推送上线，从 `1/2` 变为 `0` 时推送离线，`1` 与 `2` 之间不推送。消息包含游戏昵称、检测变化的北京时间和当前段位。状态字段缺失及查询失败不会被当作离线；失败的状态消息不积压补发。

资料的 `hideMatch` 属于游戏内隐私提示，不能单独判断营地战绩是否可见。战绩订阅始终继续请求战绩接口；返回空列表时提示可能隐藏或暂无记录，保留已有推送游标并继续后续轮询，恢复有记录时只处理最新的一场。

战绩每次只比较最新已完成对局，以 `game_seq` 去重；消息包含昵称、游戏模式、对局时间、胜负、击杀/死亡/助攻及荣誉。首次关联会话先建立基准，不推送旧战绩；之后发生查询/发送失败，恢复时也只发送当时最新的一场，不补推中间缺失的多场。发送成功的记录及会话关联写入 SQLite，重启后继续去重；解除后重新关联时重新建立基准，跳过暂停期间的记录。

主动推送消息格式如下，“时间”使用北京时间；状态消息记录检测时刻，战绩消息使用接口返回的对局时间：

```text
【上线推送】
游戏昵称：示例玩家
时间：2026-10-09 18:00:00
上线段位：最强王者 24星
```

```text
【离线推送】
游戏昵称：示例玩家
时间：2026-10-09 18:30:00
离线段位：最强王者 24星
```

`1↔2`、未知状态、查询失败都不会产生上下线通知。

```text
【战绩推送】
示例玩家-排位赛-2026-10-09 18:20
胜利
战绩：8/2/9
荣誉：MVP · 金牌中路
```

失败时第三行显示 `失败`，没有荣誉时显示 `荣誉：无`。不会自动为推送对局调用 AI 分析。

在插件配置的 **订阅系统** 设置两类轮询间隔，单位秒，默认状态 60 秒、战绩 120 秒。网页状态每 5 秒刷新，页面刷新不改变营地轮询间隔。卸载插件会停止轮询并释放资源。

### AI 对局分析

先在插件配置的 **AI 对局分析** 中选择模型。网页入口位于“玩家查询 → 战绩 → 单局详情”顶部右侧，点击“分析本场”；聊天发送 `分析 489048724 1`，只输出分析结论，不发送双方详情图片。两种入口调用相同服务和模型，普通战绩查询不再自动调用模型，旧版锐评功能和配置已移除。 单局页面打开后即可分析，无需先进入对局回放；结果显示在比赛摘要下方，由概览和回放两页共用。点击按钮时后台按对局标识重新获取详情及回放数据。

提示词分为两层：程序内固定的 `system_prompt` 解释字段、时间、坐标、伤害口径和数据限制，不提供页面查看或修改入口；可编辑的 `analysis.prompt` 定义分析任务，默认以职业教练视角输出获胜原因、关键转折、失利原因和有证据支持的责任判断。默认格式如下，首行由程序填入真实时间、模式与查询玩家本局所用英雄；原样保存的旧默认提示词会自动升级，自定义提示词保留：

```text
【2026-10-04 16:20】-【排位赛】-【鲁班大师】
【【获胜方】】
【原因】：
【关键点】：
【【失败方】】
【原因】：
【关键点】：
【背锅】：
```

输入包含双方实际返回的统计、最终装备与技能、营地表现评价、全员轨迹、全部规范化事件、死亡 / 复活点和塔位时间线。普通轨迹每 5 秒采样，额外保留首尾、断点及关键事件起止 / 死亡 / 复活时刻附近的原始秒点；坐标保留两位小数，输入注明原始和发送点数。页面播放仍使用原有每秒轨迹。模型不会收到图片链接、登录态或账号凭据。

固定说明要求模型区分不同伤害与承伤口径；建筑事件记录可能重复，不能按条数计算推塔数；位置接近不能自动等同于参战，视野、兵线和技能施放等缺失信息不能编造。缺少双方详情、回顾或可靠胜负时不给出假设性的综合分析；证据不足时默认提示词要求写“无法确定”，不只凭 KDA 给辅助或前排定责。

网页和 `分析` 指令的成功结果统一写入 `data/plugin_data/astrbot_plugin_gok/gok.db`，以对局唯一 ID `game_seq` 为主键，插件重启后仍可读取。同一场再次分析时优先返回数据库结果，不重复调用模型；聊天按序号分析时先查询详情确认当前对局 ID。同一场的并发请求共用结果，失败、超时及格式不合格的回答不会保存。缓存从结果保存时间起默认保留 150 天，可通过 **AI 对局分析 → 分析结果保留天数** 修改，读取不会延长保留期；启动时、每小时及读取时清理过期结果。

单局详情顶部依次显示“分析本场”“分析结果”“清除缓存”。没有缓存时后两个按钮禁用；已有缓存时“分析本场”禁用。“分析结果”读取已保存文字，“清除缓存”删除当前对局结果并恢复分析入口。修改提示词或模型后，需要清除该场缓存才能重新分析。

分析输入较长，建议选择支持 128k 上下文的模型，具体取决于对局长度和事件数量。网页采用后台任务与进度轮询，模型生成最长等待 180 秒，同时最多 3 个任务；任务进度在内存中保留 15 分钟，最多 32 条，任务过期不影响数据库中的分析结果。离开当前对局会停止页面轮询，卸载插件会取消进行中的任务。模型异常、空回答或默认格式不符合要求时会给出明确提示，可自定义提示词改变输出格式。

```
指令 ──► GokService（实时查询，不缓存）
            ├─► CampDataApi ──► CampClient ──► kohcamp.qq.com
            │        （encodeParam 加密、响应解密、错误码、换号重试）
            └─► GokStorage（SQLite：角色别名、AI 分析结果）
分析 ──► BattleAnalysisService ──► 先读 SQLite，未命中时查询同场数据并调用模型
```

- **加密协议**：请求头 `encodeParam` = XXTEA(`{timestamp,nonce}`, 密钥 = `userKey`)；
  未登录时用 `specialEncodeParam` = RSA-PKCS#1 v1.5（1024 位，分块）。
  响应头 `campencrypt: true` 时用同一个 `userKey` 做 XXTEA 解密。
- **微信登录**：`getwxsdkticket` → 微信 `qrconnect` 取二维码 → 轮询 `l/qrconnect`
  → `user/login` 换 `userId`/`token`/`encodeRes` → 从 `encodeRes` 解出 `userKey`。
- **QQ 登录**：独立浏览器会话取得二维码与授权码 → YSDK 换取 QQ 凭据
  → 营地 `user/login` 换票并解出 `userKey`，成功保存后关闭浏览器。
- **实时翻页**：营地战绩接口提供 `hasMore` + `lastTime` 游标，插件每次从最新战绩
  开始按游标翻页，每页间隔 400ms 以防频控。
- **实时查询**：不落库、不聚合、不增量同步；营地侧数据一变，下一次查询就能看到。

## 常见问题

**ZIP 安装报 `No matching distribution found for playwright<2,>=1.51`**
AstrBot 的 pip 未找到符合依赖要求的 Playwright Python 包。检查实际运行 AstrBot 的 Python 环境、包索引源和系统平台，并在同一个环境中安装 `requirements.txt`。本插件保留 Playwright 为必装依赖；安装 Python 包成功后，QQ 登录还需可用浏览器。

**QQ 登录提示找不到浏览器**
优先使用运行 AstrBot 的系统中已有 Chrome、Edge 或 Chromium；没有可用浏览器时，在 AstrBot 的 Python 环境运行 `python -m playwright install chromium`。容器中需将浏览器和所需系统库安装在运行插件的同一环境中，再重载插件。

**AI 提示选择分析模型 / 模型调用失败**
在插件配置的“AI 对局分析”中选择已配置且可用的对话模型，保存并重载插件。分析不使用聊天会话的默认模型作为替代。较长对局需要足够的模型上下文容量；可选择支持长上下文的模型或检查提供商返回的错误。

**AI 分析缺少回顾或返回格式错误**
缺少双方详情、对局回放或可靠胜负时，插件会说明原因，稍后重试或选择另一场。默认分析采用固定格式校验；模型输出不符合要求时提示重试，自定义提示词可以调整输出格式。网页断线后“重试连接”会继续读取原任务，任务过期后需重新分析。

**已经订阅却没有推送**
确认在“会话推送”中为完整会话 ID 勾选了目标订阅；只有营地 ID 而没有接收会话时，页面显示“已暂停”。首次检查只建立基准，需要后续发生状态变化或出现新完成对局才推送。查看两类模块的轮询时刻、目标查询错误及会话发送错误；状态 `1↔2` 不推送，隐藏战绩也无法绕过。

**故障期间遗漏的战绩会补发吗**
不会补发历史队列。例如上一条成功发送 A，期间 B、C 失败，恢复后最新是 D，只尝试发送 D。若最新一场尚未发送成功，下次轮询仍只尝试当时最新的一场；状态消息失败则直接丢弃。暂停后重新关联的会话重新建立基准。

**修改模型或提示词后，分析结果没有变化**
缓存以对局唯一 ID 为键，模型、提示词和查询玩家变化都不会让同一场自动重新生成。到详情页点击“清除缓存”，然后点击“分析本场”。任务状态的 15 分钟寿命与结果缓存的默认 150 天保留期相互独立。

**GitHub 提示 Tencent WeChat API App ID 泄露**
`APPID_WX` 是营地微信客户端的公开应用标识，用于二维码请求的 `appid` 参数，不是 AppSecret 或个人账号 token。源码迁移和文档引用可能让同一告警包含多个历史位置。核对告警只包含这个公开标识后，可在 GitHub 的“Close as”中按误报关闭并注明用途；不用修改登录所需的 AppID。真实登录态 `camp_auth.json` 仍不得提交。

**查询提示「尚未登录王者营地」**
先在插件页面扫码登录；若刚登录仍提示，检查 `data/plugin_data/astrbot_plugin_gok/camp_auth.json`
是否存在且非空。

**提示「该召唤师隐藏了个人战绩」**
对方在营地里关闭了战绩公开，插件无法绕过。
资料的 `hideMatch` 提示游戏内隐私设置，不能据此跳过营地战绩查询。需要实际请求战绩列表后再判断是否有可读记录；空列表也可能是暂无近期记录。战绩订阅遇到空列表仍保留关联并继续轮询。

**提示「操作过于频繁」**
营地侧频控。再登录一个营地账号让插件自动切换，或隔一会儿再查。

**图片发送失败**
检查 AstrBot 的文转图（t2i）服务是否可用；可把 `image.format` 改为 `png` 或调低清晰度重试。

**营地改版后查询失效**
营地接口与加密参数可能变动。相关常量集中在 `core/camp_client.py`、
`core/camp_login.py` 与 `core/camp_crypto.py`，便于对照更新。
